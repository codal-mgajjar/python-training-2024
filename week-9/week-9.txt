- M2M working
    - When you define a basic Many-to-Many relationship without specifying a through model, Django automatically creates an intermediary table.
    - If you want to add extra fields or behavior to the intermediary table, you can create a separate model and use it as the through model. This allows you to store additional information about the relationship.
- Added book-author model for M2M working
- Added Product-category model for M2M through working
- M2M field parameters 
    - related_name : use for the reverse relation from the target model 
    - related_query_name :  it sets the name for the reverse relation when querying
    - through : Specifies a model to use as the intermediate table for the M2M relationship
    - symmetrical=True : Adding a relation from one model automatically creates a reverse relation
    - db_table : Sets the name of the database table to use
    - db_constraints :  disables the database constraints for the M2M relationship
    - limit_choices_to : Dictionary of lookup arguments to limit the choices

    class BookAuthor(models.Model):

    from django.db import migrations
    import datetime


    def create_through_relations(apps, schema_editor):
        Book = apps.get_model('shop', 'Book')
        Author = apps.get_model('shop', 'Author')
        for author in Author.objects.all():
            for book in Author.books.all():
                Author(
                    a=book,
                    author=author,
                    date_joined=datetime.date.today()
                ).save()

    class Migration(migrations.Migration):

        dependencies = [
            ('shop', '0021_bookauthor'),
        ]

        operations = [
            migrations.RunPython(create_through_relations, reverse_code=migrations.RunPython.noop),

        ]
